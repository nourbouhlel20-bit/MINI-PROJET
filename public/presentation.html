🎯 Objectif

Objectif du Projet

Développer une application web moderne avec Next.js déployée dans un environnement Docker Devcontainer standardisé, garantissant une reproductibilité totale sur toutes les machines de développement.

  • Créer une application web complète avec routing, pages et API intégrée
  • Standardiser l'environnement de développement avec Docker
  • Mettre en place une suite de tests automatisés avec Jest
  • Assurer la qualité et la maintenabilité du code
02 / 12
❓ Problématique

Problématique

⚠️

Problème d'environnement

Chaque développeur utilise des versions différentes de Node.js, causant des bugs imprévisibles et du temps perdu en configuration.

🔄

Manque de standardisation

"Ça marche sur ma machine" — L'absence d'environnement partagé rend la collaboration difficile et non reproductible.

🧪

Absence de tests

Sans tests automatisés, chaque modification risque de casser des fonctionnalités existantes sans le détecter.

📡

Communication Frontend/Backend

Intégrer une API REST directement dans l'application sans serveur externe complexifie l'architecture.

💡 Solution

Solution Proposée

⚛️

Next.js 14

Framework React avec routing automatique, API Routes intégrées et rendu côté serveur (SSR).

🐳

Devcontainer

Environnement Docker partagé : même Node.js, mêmes outils, même configuration pour tous.

🧪

Jest + RTL

Tests unitaires et d'intégration automatisés avec React Testing Library pour garantir la qualité.

✨ La combinaison Next.js + Devcontainer résout simultanément les problèmes d'environnement, d'architecture et de qualité du code.

⚠️ Difficultés

Difficultés Rencontrées

🔧

Configuration Babel + SWC

Next.js 14 désactive automatiquement SWC quand un fichier babel.config.js est présent. Nécessite une configuration manuelle pour Jest.

🎭

Mock de fetch dans Jest

Le mock de global.fetch dans l'environnement jsdom nécessite une configuration spécifique avec jest.fn().mockResolvedValue().

🐳

Compatibilité Docker

La configuration du port forwarding et des volumes dans le Devcontainer sur Windows avec WSL2 a nécessité plusieurs ajustements.

💡 Leçon apprise : La documentation officielle de Next.js et les issues GitHub ont été des ressources précieuses pour résoudre ces blocages techniques.
